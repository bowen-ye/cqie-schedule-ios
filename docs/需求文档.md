# 教务课表查询 App（Android APK）需求文档

> 版本：v0.1（待评审草稿）　日期：2026-09-07
> 背景系统：重庆工程学院教务（`njw.cqie.edu.cn`），「CAS 统一认证 + OAuth2 + 教务 SPA」架构（与 `E:\software\抢课脚本` 同一套后端，登录链与课表接口均已逆向可用）。
> 状态：**v0.1 供你逐条检查**。文末「§8 待你确认的问题清单」是需要你拍板的项，其余为推荐默认值。

---

## 0. 一句话目标

做一个**能装在手机上的课表查询 App**：学生用自己的学号登录一次，之后打开 App 直接看本周/某周课表，不用再每次去教务网页系统里翻。**只读查询，不做选课/抢课等写操作**。

---

## 1. 背景与痛点

1. 学生的课表目前只在教务网页系统里，要看必须先 PC/浏览器 登录教务系统，进入 SPA 层层点开，**手机上尤其难用**（教务网页对移动端适配差、登录体验差）。
2. 已有成熟逆向成果可直接复用，不必从零摸接口：
   - 完整登录链已破解并封装（CAS 登录 → OAuth2 → Bearer token，**token 有效期约 7 天，可 refresh**）。
   - **课表接口已确认可用**：`POST https://njw.cqie.edu.cn/api/timetable/class/timetable/student/my-table-detail?sessionId=1087`，返回结构已拿到真实样例（`njw_timetable_1087.json`），字段能直接支撑渲染周课表。
3. 查课表是**低频只读操作**，对教务服务器几乎无负载，触发风控风险远低于抢课场景；但账号安全、登录体验仍是设计重点。

## 2. 范围

### 2.1 本期（v1.0，本 App）做
- 账号登录 / 自动续期
- 当前学期课表抓取与解析
- 周课表视图（本周 / 切换周次）
- 课程卡片详情
- 今日/即将上课一览
- 线上课（无固定时间排课）单独展示
- 离线缓存（断网也能看最近一次课表）

### 2.2 明确不做（v1.0）
- ❌ 选课 / 退课 / 抢课等一切**写操作**
- ❌ 成绩查询、考试安排、空闲教室查询（可留作 v2 扩展）
- ❌ 云同步 / 多端
- ❌ iOS / 鸿蒙 HarmonyOS NEXT（**apk = 仅 Android**，见 §8 Q4）

### 2.3 可选增强（排期靠后，见 §7）
- 上课前提醒通知（到点前 N 分钟）
- 多账号切换（一般不需要，默认单账号/单设备）
- 深色模式、桌面小组件

## 3. 用户与场景

### 3.1 角色
- **唯一角色：在校学生**（自己账号）。单设备单账号。默认不自带「帮别人查」的能力——别人用就要登录他自己的账号。

### 3.2 核心使用场景（按频次排序）
| # | 场景 | 频次 |
|---|---|---|
| S1 | 早上出门前：**今天几节课、几点、在哪个教室** | 每天 |
| S2 | 临时想确认**下节课（下一门）在哪个教室/几点** | 每天多次 |
| S3 | 老师调课后，想知道**本周后面几天**还有什么课 | 每周数次 |
| S4 | 开学时一次性登录，之后不再碰教务网页 | 每学期 1 次 |

### 3.3 用户故事（评审用）
- 作为学生，我**登录一次**，此后 7 天内打开 App 直接看课表（token 到期自动刷新，刷新失败才重新走登录）。
- 作为学生，我能左右滑动/点击切换**某一周**的课表，也能一键回到「本周」并看到「今天是星期几、当前第几周」。
- 作为学生，我点任意一节课的卡片能看到：教室、校区、上课节次时间、周次范围、老师、学分、课程代码。
- 作为学生，我在**网络断开时**仍能看上一次加载成功的课表（离线缓存）。

## 4. 功能需求（FR）

### FR-1 登录与令牌
| 编号 | 需求 |
|---|---|
| FR-1.1 | 首次使用弹出**官方教务登录页**，学生用**自己的** CAS 学号/密码登录（含官方的图形验证码）。 |
| FR-1.2 | 登录成功后 App 拿到 `access_token`（≈7 天有效），**保存于系统安全存储**（Android Keystore + 加密首选项），不写明文、不打日志。 |
| FR-1.3 | token 快过期时用 `refresh_token` **静默续期**；续期失败/过期才引导重新登录，并提示原因（密码改了 / 长时间未用）。 |
| FR-1.4 | 提供「退出登录」，退出即清除本地 token 与缓存课表。 |

> 设计说明：**推荐「内置官方登录页 WebView 完成认证」，而不是在 App 里重新实现 DES 加密 + 表单**。理由：
> - 教务登录页的验证码、字段名、加密若变动，WebView 始终跑的是官方最新前端，**App 不会被一次改版打死**（原生复刻 DES/表单才是脆弱路径）；
> - App **不接触明文密码**（密码在官方页面里填，只经过官方 JS 加密），安全边界最干净。
> 原生复刻登录作为 B 方案保留，仅当 WebView 捕获 token 在技术上受阻时才启用（此路径 DES ECB+PKCS7 现成，见仓库 `njw_login.py`，成本可控）。

### FR-2 学期 / 周次模型
| 编号 | 需求 |
|---|---|
| FR-2.1 | App 内可**选择学期**（从服务端当前可用的学期/批次中枚举；默认「当前学期」）。 |
| FR-2.2 | **自动计算当前教学周**：读教务官方接口 `/api/timetable/time/cur-week`（返回值 `data` 为 `{"周":"…"}` 字典，取其**第一个 key** 即当前周，与教务 SPA 同源）。由「当前周 + 今天日期」反推本学期第 1 周周一（本周一 −(当前周−1)×7 天），作为日期基准。打开 App **自动跳到当前周**，无需用户填开学日期。 |
| FR-2.3 | 支持周次 1~学期总周数（如 20 周）自由切换查看。 |

### FR-3 课表抓取与解析
| 编号 | 需求 |
|---|---|
| FR-3.1 | 从课表接口拉取该生全部课程排课（含必修/选修/体育/实践等，只要接口返回的都算）。 |
| FR-3.2 | **解析规则**：以接口返回的 `teachingWeekFormat`（如 `1-16`/`13-15`/`20`）、`weekDay`、`periodFormat`（如 `7-8`）为准，**不依赖**需要按周数扩展的位掩码字段 `teachingWeek`/`period`（后端已直接给格式串，直接用）。 |
| FR-3.3 | **线上课 / 无固定排课行**（样例里存在 `weekDay=""`、无教室、整学期排布的网课行）不放进时间格，单独收进「线上 / 待定课程」分组，卡片上标注课程名/学分/老师。 |
| FR-3.4 | 同一门课跨多行（如某课 1-9 周周三 + 10 周周六分开返回）在**课程详情里合并展示全部时间段**，时间格仍按各条独立摆放。 |
| FR-3.5 | 同一时间格若出现多门课（冲突/异常），格子内最多展示两门，多的折叠，可展开查看。 |

### FR-4 视图与交互
| 编号 | 需求 |
|---|---|
| FR-4.1 | **Tab 1「周课表」**：横轴周一~周日、纵轴第 1~N 节（有课最多到几节自动扩，上限 12~14）；顶部显示「第 X 周」+ 左/右切换 + 回到今天按钮；**高亮今天那一列**（当查看的正好是当前学期 + 当前周时，整列淡蓝提亮 + 表头标「今天」，打开自动定位到该状态）。时间列显示官方时刻。课程格只在本周出现的周次显示。 |
| FR-4.2 | **Tab 2「今日」**：按节次列出今天课程（含已过/未到节次标记）+「**下一节课**」置顶卡片（现在几点的判断要简单可靠）。当天没课则给一句明确文案。 |
| FR-4.3 | **课程详情页**：课程名、周次、星期+节次、教室与楼栋、**校区**、任课老师、学分、课程代码、开课院系；若属线上课则说明「线上学习，无固定教室」。 |
| FR-4.4 | 下拉刷新重新拉取；拉取失败给出可操作错误提示（网络不可达 / 登录过期 / 服务器暂不可用），不清空已有缓存内容。 |
| FR-4.5 | 空/加载/错误三态都有明确占位 UI。 |
| FR-4.6 | **手动补录课程/任务**：点击周课表任意空白格（或工具栏「＋手动添加」）弹出添加框，填名称、类型（课程/任务/备忘）、星期、第几节到第几节、周次（留空=每周，支持 `1-16`/`1,3,5`/`8`）、地点/备注，可自选配色，存入本机并即时上图。点已添加的卡可再编辑/删除。用于补教务里查不到的临时课、开会、自习、背单词等。数据仅存本地，与教务抓取的课区分显示（虚线+标记）。 |

### FR-5 离线与性能
| 编号 | 需求 |
|---|---|
| FR-5.1 | 每次成功拉取后把**解析好的课表写入本地**；冷启动直接先渲染本地缓存（秒开），再后台静默刷新。 |
| FR-5.2 | 正常刷新频率低（下拉手动为主，可加一个「App 打开自动刷新但 24h 内不重复」的节流），不打扰教务服务器。 |

### FR-6 设置（作息/周次不再手填）
- 节次↔时刻**自动读取**教务官方接口 `/api/resourceapi/timePattern/get-large-period`（`data[0].periodList` 的 `smallPeriod/type/startTime/endTime`），时间列与「几节↔几点」据此显示，无需用户编辑。
- 当前教学周自动取自官方 `cur-week`（FR-2.2），同样不手填。
- 可选设置仅剩非作息类项：是否隐藏某校区课、是否显示「线上课」分组开关、深色模式（跟随系统）、退出登录。

## 5. 非功能需求（NFR）

| 项 | 要求 |
|---|---|
| **平台** | Android（minSdk ≥ 26 / targetSdk 建议 34），仅 APK；断网、弱网可用（见 FR-5）。 |
| **安全** | token 存系统安全区；**任何日志/崩溃上报不含 token/账号/课表内容**；仅 HTTPS；无第三方统计 SDK（或不含个人信息）；课程内容不外发。 |
| **隐私合规** | 只保存登录者本人账号数据于本机；不采集、不上传任何信息到除教务官方服务器外的任何服务器。 |
| **可用性** | 冷启动（有缓存）≤ 2s 出课表；登录/网络/过期错误文案对普通学生友好。 |
| **健壮性** | 教务接口偶发慢/失败时能重试、能降级到缓存；App 崩溃不影响已缓存课表。 |
| **可维护** | 教务域名/接口路径/节次表等**集中在一处配置**（仿照 `抢课脚本` 顶部常量做法），便于换学校或应对后端微调。 |

## 6. 技术方案（评审重点）

### 6.1 已确认的接口资产（来自 `抢课脚本`，可复用）
```
[登录链] WebView 内走官方页面完成（推荐）
  若走原生 B 方案才需复刻：authserver/casLogin → a.cqie.edu.cn CAS（DES+lt+execution+验证码）
  → 换票 → /workspace/cas → OAuth2 authorize→code → /oauth/token → Bearer access_token(≈7d)

[课表]  POST /api/timetable/class/timetable/student/my-table-detail?sessionId={学期Id}
        头: Authorization: Bearer {token}
        体: {}  →  返回 classTimetableVOList[]  （结构见下，样例已存 njw_timetable_1087.json）
```
- 需在**实现期补抓 1~2 个接口**：如何枚举「可选学期/批次」拿到各学期 `sessionId`（预研：`/api/enrollment/enrollment-batch/session-list` 与身份接口，需确认其是否覆盖全部开课学期，否则从课表模块找学期列表接口）。→ 已列入任务 F1/F11。

### 6.2 课表行数据结构（渲染所需字段）
| 字段 | 含义 / 用法 | 样例 |
|---|---|---|
| `courseName` | 课程名 | 网络爬虫技术 |
| `courseCode` `classNbr` | 课程/教学班编码 | `20210002` / `603164-001` |
| `weekDay` / `weekDayFormat` | 星期（1-7）/中文 | `1` / `一` |
| `periodFormat` | 节次（渲染格纵向位置） | `5-6`、`7-8` |
| `teachingWeekFormat` | 周次范围（判“本周是否有课”） | `1-16`、`13-15`、`20` |
| `teachingWeek` / `period` | 位掩码（**备选**，不优先用） | `111...`/`00000011` |
| `roomName` `roomLabel` | 教室 / 教室类型 | `6211` / `智慧教室` |
| `campusName` | 校区 | 南泉校区 |
| `instructorName` | 老师（串，需清洗“工号[主讲]”后缀） | `郑金丽-05146[主讲];` |
| `credit` | 学分 | `2.0` |
| `courseDepartmentName` | 开课院系 | 马克思主义学院 |
| （空 `weekDay`+无教室的行） | **判为线上/无固定排课** | 演讲与口才 |

### 6.3 两种架构对比
| 维度 | **A. App 直连教务 API（推荐 v1）** | B. App + 自建中转后端 |
|---|---|---|
| 架构 | APK 内 WebView 登录→存 token→OkHttp 直连课表接口 | APK → 自己服务器 → 教务 |
| 优点 | 零服务器、零运维、成本最低；只读低频无风控压力；复用全部已验证接口 | 可集中管理多账号/缓存/做更多业务；弱网可控 |
| 缺点 | 登录态存各手机本地，7 天一刷新；多人分发=每台各登各的 | **需要一台 24h 在线的机器**（你的脚本机不能常开）；服务器反代你的账号反而扩大泄露面 |
| 结论 | **默认选 A** | 仅当你后续想“帮全班批量查/抢课”时再评估 |

### 6.4 客户端技术栈（三选一，见 §8 Q3）
| 方案 | 说明 | 适合 |
|---|---|---|
| **Kotlin + Jetpack Compose**（原生） | 无壳轻量、WebView+OkHttp+Keystore 都是原生一等公民 | 想做个正经 App、长期维护 |
| **Flutter** | 跨端统一、UI 开发快；鸿蒙/未来扩展方便 | 想要快、想以后覆盖更多端 |
| **Android WebView 壳 + 本地 H5** | 纯 HTML/JS 拉官方接口（复刻 py 逻辑）+ 壳提供 token 存储 | 最快出原型，但安全/体验弱，不建议作正式版 |

> 无论选哪个，**登录都走官方页面 WebView**，不因技术栈而改变（§4 FR-1.2 说明）。

### 6.5 关键实现风险与对策
| 风险 | 对策 |
|---|---|
| WebView 捕获 OAuth token 的具体时机/URL 需现场确认（workspace 前端如何落 token 到 SPA 的机制） | 实现期先在 PC 上 `playwright` 走通「登录→取 token」全流程，把「哪一步 URL/localStorage 出现 access_token」记死，再照搬到 WebView（优先级 F2）。 |
| token 由 refresh_token 静默续期未必每次都成功 | 失败即转「重新登录」页，文案友好；不阻塞用户看已缓存课表。 |
| 学期列表接口归属不明 | 见 F11，抓包定位；若不可得，退化为「当前学期写死 + 手填 sessionId」。 |
| 不同学期/校区作息（第几节几点）不一致 | 运行时从教务 `get-large-period` **自动读取**当前作息并缓存；接口失败时用内置默认作息兜底（内容与教务一致），见 FR-6。 |

### 6.6 合规与安全边界（沿用抢课仓库既有纪律）
- 只登录**本人**账号、只读本人课表，与「抢课」仓库免责声明口径一致；**不聚合他人账号、不批量抓取**。
- 代码与仓库**不含真实账号/密码/token**；发布仓库用变量/占位；`gitignore` 掉一切 token、课表快照、日志。
- App 内不做任何把账号共享/托管的服务化设计。

## 7. 里程碑建议（评审时可调）

| 阶段 | 内容 | 产出 / 验证 |
|---|---|---|
| M0 技术预研（半天~1天，PC 上做） | 用 playwright/requests 跑通：选学期→拉课表→解析周课表模型；确认学期列表来源；**确认 WebView 取 token 时机** | 一张「接口+字段+取 token 步骤」结论表，作为本 App 开发依据 |
| M1 登录闭环 | 选技术栈（§6.4）；WebView 登录→取/存 token→静默续期→退出 | 模拟器上完成一次「登录→看 token 落地」 |
| M2 数据层 | 接口调用 + 解析 + 周课表数据模型 + 本地缓存 | 单测：真实学期数据正确渲染模型 |
| M3 UI 三屏 | 周课表 / 今日 / 课程详情 + 三态 + 下拉刷新 + 设置 | 真机每周视图正确、切周正确、线上课正确归组 |
| M4 打磨 | 离线、深色、错误文案、性能、加固/混淆 | Beta 给 1~2 个同学试一周 |
| M5（可选 v1.1） | 上课前提醒通知、小组件 | — |

验收标准（摘自 FR）：登录一次→不手动登录连续使用 ≥7 天；本周课表与教务网页**一致**；任意切周无错位；今天「下一节课」判断正确；飞行模式下仍能看最近课表。
